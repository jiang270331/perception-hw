## 一、点云是什么

**一句话：一大堆三维坐标点的集合。**

```
点云 = [(x₁, y₁, z₁), (x₂, y₂, z₂), ..., (xₙ, yₙ, zₙ)]
    ↓
每个点还可以带额外信息：颜色 (r,g,b)、法向量 (nx,ny,nz)、强度 (intensity)、时间戳
```

**怎么得到点云：**

| 设备 | 原理 | 特点 |
| --- | --- | --- |
| **激光雷达（LiDAR）** | 发射激光，测往返时间 → 距离；扫描角度已知 → 方向 | 精度高、范围远、不受光照影响；贵、雨雾差 |
| **深度相机（RGB-D）** | 结构光 / ToF / 双目，得到每像素深度 | 便宜、稠密；范围近（< 10 m）、受光照影响 |
| **双目立体** | 两个相机视差算深度 | 便宜；远处精度差、纹理少的地方失效 |
| **SFM / 多视图** | 多张照片重建 | 离线、精度高；慢 |

**★ 我们车队那 4 个「深度相机」如果输出深度图，转点云的公式就是：**

```
X = (u - cx) * d / fx
Y = (v - cy) * d / fy
Z = d
    ↓
(u,v) 是像素坐标，d 是深度，fx/fy/cx/cy 是内参
```

## 二、点云和图像的区别（这条最重要）

| | **图像** | **点云** |
| --- | --- | --- |
| **数据结构** | **规则网格**（H×W×3），每个像素有确定位置 | **无序点集**（N×3），点之间没有网格关系 |
| **邻域** | 上下左右 4 邻居、8 邻居，直接索引 | **要自己找**（k近邻 / 半径搜索），慢 |
| **分辨率** | 均匀（每个像素一样大） | **不均匀**（近处密、远处稀） |
| **维度** | 2D 投影（丢了深度） | **真 3D** |
| **稀疏性** | 稠密（每个像素都有值） | **极稀疏**（大部分空间是空的） |
| **顺序** | 有（行优先） | **无**（同一堆点，换个顺序还是同一堆） |
| **光照** | 直接影响（阴影、过曝） | LiDAR 不受影响；深度相机受影响 |
| **语义** | 直接有颜色纹理 | 没有纹理，只有几何 |

**★★ 最关键的差异：**

```
图像是「网格」，所以卷积核可以直接滑
    ↓
点云是「点集」，没有网格，卷积没法直接用
    ↓
★ 这就是 PointNet / PointNet++ / VoxelNet 这些方法要解决的问题
（要么把点云体素化变成网格，要么设计能处理无序集合的网络）
```

**★★★ 另一个关键差异：稀疏性。**

```
一张 640×480 的图 = 30 万像素，每个都有值
一台 64 线激光雷达转一圈 ≈ 10-20 万点，撒在几十米范围里
    ↓
★ 点云里 99% 的空间是空的
★★ 所以「怎么高效处理稀疏数据」是点云的核心工程问题
（→ 稀疏卷积 spconv / MinkowskiEngine）
```

## 三、PCL 主要解决什么问题

**PCL = Point Cloud Library，一个开源的 C++ 点云处理库（也有 Python 绑定 `python-pcl`，但维护不如 C++ 版活跃）。**

**它提供的东西大致分五类：**

### 1. I/O（读写）

```
读 .pcd / .ply / .las 文件
从 ROS 的 sensor_msgs/PointCloud2 转换
存成各种格式
    ↓
★ .pcd 是 PCL 自己的格式（Point Cloud Data），支持 ASCII 和二进制
```

### 2. 滤波（filtering）

**去掉不想要的点。**

| 滤波器 | 干什么 |
| --- | --- |
| **PassThrough** | 只保留某个坐标范围内的点（比如「只要 z 在 0.5-10 m 的」） |
| **VoxelGrid** | 体素降采样（下面细说） |
| **StatisticalOutlierRemoval** | 去掉离群点（统计每个点到 k 个邻居的平均距离，太远的删掉） |
| **RadiusOutlierRemoval** | 去掉「邻居太少」的点（半径 r 内邻居 < N 就删） |
| **ConditionalRemoval** | 按自定义条件删 |
| **BilateralFilter** | 保边去噪（像图像的双边滤波） |

### 3. 降采样（downsampling）

**点太多算不动，先变少。**

**最常用：`VoxelGrid`**

```
把空间切成小立方体（体素），每个体素里所有点合并成一个点（通常是质心）
    ↓
例：10 万个点，2 cm 体素 → 可能只剩 2 万个
    ↓
★ 关键：体素大小是核心参数
   太小 → 没减少多少，还是慢
   太大 → 细节丢了（小障碍物消失）
```

**★★ 这个和图像里的「降采样」不一样：**

```
图像降采样：每 2×2 像素取平均 → 变成一半大小
点云降采样：空间网格聚合 → 点数变少，但每个点还是 3D 坐标
```

### 4. 分割（segmentation）

**把点云分成「不同的部分」。**

| 方法 | 干什么 | 典型用途 |
| --- | --- | --- |
| **平面分割**（RANSAC） | 找出最大的平面 | 去掉地面（地面占了 50% 以上的点） |
| **欧式聚类** | 按空间距离分组 | 把点分成一个个「物体」 |
| **区域生长** | 按法向量/曲率相似性生长 | 分割出平滑表面 |
| **圆柱/球体检测** | 拟合几何形状 | 找电线杆、球 |

**★ 地面分割是激光雷达感知的第一步** —— 不把地面去掉，后面聚类会把整个地面当成一个巨大物体。

### 5. 聚类（clustering）

**严格说聚类是分割的一种。** `EuclideanClusterExtraction`：

```
1. 随机取一个没访问过的点，作为种子
2. 找它半径 r 内的所有点，加入同一个簇
3. 对新加入的点重复第 2 步（BFS/DFS 生长）
4. 簇不再增长 → 一个物体
5. 回到第 1 步，直到所有点都被访问过
    ↓
★ 参数：r（聚类半径）、min_size / max_size（簇大小过滤）
```

**★★ 聚类半径要和「物体之间的间距」匹配：**

```
r 太小 → 一个物体被切成好几块（欠聚类）
r 太大 → 相邻物体被合并（过聚类）
```

### 6. 其他（注册 / 特征 / 配准）

| 功能 | 干什么 |
| --- | --- |
| **ICP（迭代最近点）** | 把两片点云对齐（配准） |
| **NDT** | 另一种配准方法（比 ICP 快，但精度略低） |
| **FPFH / SHOT 特征** | 算每个点的局部特征描述子（用于匹配） |
| **KdTree / Octree** | 加速最近邻搜索的数据结构 |

## 四、这些处理在激光雷达感知里的用途

**典型流程（一个激光雷达感知 pipeline）：**

```
原始点云（10 万点/帧）
    ↓  ① PassThrough（只保留车前 0.5-50 m）
    ↓  ② VoxelGrid（10 cm 体素，降到 2 万点）
    ↓  ③ StatisticalOutlierRemoval（去噪）
    ↓  ④ RANSAC 平面分割（去掉地面，占 50%+）
    ↓  ⑤ EuclideanCluster（聚成一个个物体）
    ↓  ⑥ 对每个簇：算包围盒、质心、尺寸 → 分类（车/人/锥桶）
    ↓
输出：障碍物列表 → 给规划
```

**每一步的作用：**

| 步骤 | 为什么必须做 |
| --- | --- |
| **PassThrough** | 车后、天上、地下的点没用，先砍掉 |
| **VoxelGrid** | 10 万点逐帧聚类太慢（> 100 ms），降到 2 万点能到 20-30 ms |
| **去噪** | 雨滴、灰尘、飞虫会产生孤立的假点 |
| **地面分割** | 不分割的话，地面是一整片连着所有物体的「巨大平面」 |
| **聚类** | 把「一堆点」变成「几个物体」 |
| **包围盒** | 规划要的是「哪里有个 1.5×0.8×1.8 m 的东西」，不是几万个点 |

**★★ 对我们车队的具体意义：**

```
A3 循迹自主需要「前面有没有障碍物，在哪」
    ↓
如果只有视觉：
  · YOLO 能检测「车/人」，但给不出准确距离（单目）
  · 深度相机能测距，但只有 5-10 m
    ↓
如果加激光雷达：
  · 能直接得到准确距离（cm 级）
  · 能检测 YOLO 不认识的「异形障碍物」（石头、水马）
  · 但规则可能不允许（要查赛道规则）
    ↓
★ PCL 就是处理激光雷达数据的基础设施
```

## 五、我的疑问（还没搞清楚的）

1. **PCL 的 Python 绑定值得用吗？**
   `python-pcl` 最后更新是 2019 年左右，可能装不上 Python 3.12。
   **替代方案**：`open3d`（Python 友好、文档好、维护活跃），功能覆盖 PCL 的常用部分（体素降采样、平面分割、聚类、ICP）。
   **待确认**：open3d 和 PCL 的功能差多少？如果够用就不折腾 PCL 的 Python 绑定了。

2. **点云的「无序性」对神经网络到底影响多大？**
   PointNet 用 max-pooling 解决无序性，但 max-pooling 会丢信息。
   体素化能变成有序网格，但会引入量化误差和稀疏性。
   **到底哪种更好？** 目前看体素化 + 稀疏卷积在检测任务上更主流（VoxelNet、PointPillars、CenterPoint）。

3. **体素大小怎么选？**
   10 cm 是常见值，但：
   - 小了算不动
   - 大了小物体消失（锥桶直径 30 cm，5 cm 体素还能看到，20 cm 体素可能就没了）
   **有没有经验公式？** 目前只看到「看你的最小目标尺寸」这种说法。

4. **地面分割在越野地形上怎么办？**
   RANSAC 平面分割假设「地面是平面」，但越野赛道有坡、坑、坎。
   **PCL 有没有更好的方法？** 看到有人用 `ProgressiveMorphologicalFilter`（专门针对地形），但没实测。

5. **实时性**
   Jetson 上跑完整 pipeline（滤波 + 分割 + 聚类）能到多少 Hz？
   看到一个说法是 Orin 上 10-20 Hz，但和分辨率、体素大小强相关，需要实测。
